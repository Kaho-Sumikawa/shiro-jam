# 後ろの白い城を白日にしろ！

Unity 1週間ゲームジャム（unity1week）参加作品
テーマ：**しろ**

---

## コンセプト

肉眼では見えないバイ菌を「顕微鏡モニター」で観察して位置を覚え、振り返って本物の白い城を除菌するゲーム。
「一度に両方を見られない」ことがゲームの核。記憶して振り返る緊張感を楽しむ。

### タイトルに込めた意味（テーマ「しろ」）
- **白**い城
- 白**日**にする（＝隠れているものを暴いて明らかにする）
- 命令形「〜**しろ**」
- 「白」の字が2回出る（白い・白日）

「白日にする」＝目に見えないバイ菌を暴いて消す、というコアループそのものを表している。

---

## コアループ

1. **観察**：手元のモニター（顕微鏡的UI）に小型の3D城。マウスで回転させ、可視化されたバイ菌の位置を覚える
2. **振り返り**：振り返ると本物の白い城。バイ菌は**完全に非表示**（肉眼では見えない）
3. **除菌**：覚えた位置をスコープで狙ってひとふき（クリック）
   - スコープはズーム倍率を変えられる（高所・小さい菌に寄って狙う）
   - **当たり**：バイ菌がパッと白い光ではじけて消える
   - **外し**（菌のない場所を撃つ）：菌が繁殖して1個増える（増えた分はモニターに反映）
4. **クリア**：すべてのバイ菌を消したら、城が「白日の下に」＝クリア

## ゲーム設計の要点

### なぜバイ菌なのか
「本物の城の汚れが肉眼で見えない」理由づけ。バイ菌は肉眼で見えない → モニター（顕微鏡）でだけ可視化できる、という設定で「見えない」に説得力を持たせる。

### 一度に両方を見られない（振り返り式）
- モニターを見ている間は本物の城が見えない
- 本物の城に対処している間はモニターが見えない
- → **記憶**でつなぐしかない。これが「後ろ」というタイトルの意味を成立させる

### 本物の城のカメラ（スコープズーム式）
- 本物の城は**固定**（城は動かさない。回すのは世界観的に不自然なので不採用）
- プレイヤーは**スコープ（除菌スキャナー）を覗く**。ズーム倍率を変えられる（カメラのFOVで実装）
- **引き（低倍率）**：城全体が見える。だいたいの位置を把握
- **寄り（高倍率）**：高所・小さい菌に寄って正確に狙う。**寄るほど視野が狭くなり、周りが見えなくなる**（トレードオフ）
- この「寄ると周りが見えない」制約が、高所問題の解決と記憶ゲームの緊張感を同時に生む
- ※梯子で登る等のキャラ移動・探索は、ジャンルが変わりスコープ外（jam後の拡張候補）

### 外し＝菌が増える
- 総当たり（当てずっぽうで全部撃つ）を防ぎ、「覚える意味」を作る
- **外した際に増えた菌も、モニターで確認できる**ようにする（理不尽さ回避）
- 増加量は **外し1回＝1個追加**（差し引きゼロの悔しさが程よい）

### バイ菌の見た目・表現
- **モニターの城**：白い城に黒い塊（バイ菌）が数個へばりついて**はっきり見える**。位置の視認性が最優先（覚える対象だから）。モニターは顕微鏡グリッド／走査線などで「観察してる感」を出す
- **本物の城**：バイ菌は**完全に非表示**。記憶だけが頼り（ストイック）
- **除菌の瞬間**：黒い菌が**パッと白い光ではじけて消える**（＋気持ちいいSE）。「白日にする」＝明るみに出す感覚を演出

### 完全非表示を理不尽にしないための死守ポイント
以下の3つで「見えないけど運ゲーではない」を担保する。どれか1つでも欠けると理不尽になるので必ず維持する：
1. モニターは何度でも見返せる（振り返れば再確認できる）
2. 外して増えた菌もモニターに反映される（外しても位置を確認しに行ける）
3. スコープでズームして正確に狙える（位置さえ覚えていれば当てられる）

## 実装スコープ（1週間・ソロ）

### 必須（MVP：まず頭からクリアまで一周動かす）
- [ ] 回せる小型城モデル（マウスドラッグで回転）＋バイ菌表示
- [ ] 振り返りカメラ（前＝本物の城／後ろ＝モニター、片方向くともう片方は見えない）
- [ ] 本物の城への除菌（クリックで当たり判定、覚えた位置と一致で消える）
- [ ] 外し＝菌+1
- [ ] クリア判定（全部消したら勝ち）
- [ ] タイトル画面／クリア画面（テキストのみで可）

### 磨き（余力の分だけ）
- [ ] バイ菌のビジュアル（かわいく／不気味に）
- [ ] モニターUI（顕微鏡・スキャナー風）
- [ ] 除菌エフェクト・SE
- [ ] 難易度カーブ（クリアするたび初期菌数を増やす。3〜5個スタート）
- [ ] スコープのズーム操作（マウスホイール等でFOV変更、寄ると視野が狭くなる）

### 難易度別（時間と気力があれば・優先度低）
Easy / Normal / Hard を選べるようにする。コアが完成していれば数値差し替えで後付けできる：
- 菌の数（例：3 / 5 / 8個）
- 制限時間の有無
- 外し時の菌増加数（+1 / +2）
- スコープの寄れる限界（Hardは寄りが弱く狙いにくい 等）

### やらないこと（スコープ外）
- 擦って落とす表現（ひとふきで即消え。塗り・マスクテクスチャは作らない）
- 汚れのリアルな塗り表現（パーツ単位 or 即消えで割り切る）

## 技術メモ

- **エンジン**：Unity（3D / Built-in Render Pipeline）
- **提出形式**：WebGLビルド（ブラウザで遊べる形）※Day7で対応
- **城アセット**：Hyper Casual Cartoon Castles（Unity Asset Store・無料）
  - 白ベースの城を使用。手元モデル用と本物用で同じ城を2つ配置
  - バイ菌を貼りやすいよう、塔・壁・屋根などパーツが分かれた城を選ぶ
- **バージョン管理**：git / GitHub（機能ひとつ動くごとにcommit）

### 除菌の当たり判定の考え方
- バイ菌は城のどのパーツ／位置に紐づくかを持つ
- 本物の城をクリック → その位置にバイ菌があれば「当たり」→ 消す
- なければ「外し」→ 菌を1個追加（追加分はモニターに反映）

## 開発スケジュール（目安）

| Day | やること |
|-----|---------|
| 1-2 | コアを動かす（回せる城＋バイ菌表示） |
| 3   | 振り返り＋除菌（当たり判定・外し＝菌+1） |
| 4   | ゲーム成立（クリア判定・タイトル/クリア画面）＝一周遊べる状態 |
| 5-6 | 磨き（ビジュアル・UI・SE・難易度カーブ） |
| 7   | WebGLビルド・提出・予備日（絶対に作業を詰めない） |

### 開発の鉄則
1. まず頭からクリアまで一周動くものを最速で作る（完璧は後回し）
2. 機能ひとつ動くごとにcommit
3. Day7は予備日として必ず空ける（ビルド失敗・提出詰まりがソロjam最大の死因）
