## どんなゲームか

部屋にはモニターがあり、画面の中にはバイ菌がくっついた白い城が映っています。
ところが後ろを振り返った先にある本物の城では、バイ菌は**肉眼ではまったく見えません**。

モニターで位置を覚え、振り返り、記憶だけを頼りに狙い撃つ。
当たればバイ菌は白い光ではじけて消え、外せばバイ菌が1匹増えます。
すべて消して、城を「白日の下に」さらせばクリアです。

### 操作方法

| 操作 | キー |
|---|---|
| 移動 | WASD |
| 視点操作 | マウス |
| 発射 | 左クリック |
| 城を回転（モニターに近づいたとき） | 左クリック + ドラッグ |
| 遊び方を表示 | Tab |

※ マウスでの視点操作と照準が前提のため、ノートパソコンのタッチパッドでは遊びにくくなっています。マウス付きのPCでのプレイをおすすめします。

## 企画のポイント

### タイトルを先に決め、そこからゲームを連想した
本作は、ゲームの仕組みより先に**タイトルから考えました**。テーマ「しろ」から言葉を広げ、1つのタイトルに3つの「しろ」を込めています。

- **白**い城
- 白**日**にする（＝隠れているものを暴いて明らかにする）
- 命令形の「〜**しろ**」

タイトルは「真っ白にしろ」「潔白にしろ」「清潔にしろ」なども候補に挙げて比べました。
「潔白」は道徳的な無実、「純白」は色としての白さを指す言葉で、どちらも「菌がいない」状態は表しません。言葉の意味がずれたタイトルは後から引っかかると考えて外しました。
最終的に「白日の下にさらす」から「白日」を選び、そこから「**見えないものを暴く → 肉眼では見えないバイ菌を、別の画面で見つけて消す**」とゲームの中身を連想していきました。タイトルの意味が、そのままコアループになっています。

### 作ったことのないジャンルに挑戦：FPS系
以前から、いろいろなジャンルのゲームを作ってみたいと考えていました。そこで本作では、一人称視点で歩き回り、照準を合わせて撃つ**FPS系**の操作に挑戦しました。

### 「一度に両方は見られない」を核にした
モニターを見ている間は本物の城が見えず、本物の城を狙っている間はモニターが見えない。
2つを**記憶**でつなぐしかない、という制約がタイトルの「後ろの」の意味であり、このゲームの緊張感の源です。

### 外すと罰ゲーム＝「覚える意味」をつくる
当てずっぽうで全部撃てば勝ててしまうと、記憶ゲームとして成立しません。
そこで「**外すとバイ菌が1匹増える**」罰ゲームを入れ、難易度を少し上げています。総当たりを防ぎつつ、増えるのを1匹に抑えることで、理不尽ではなく「悔しい」と感じる程度に調整しました。

### 「見えない」を理不尽にしないためのルール
バイ菌を完全に非表示にすると、下手をすると運ゲーになります。そこで次の点を「絶対に崩さない設計」として決めてから作りました。

1. **モニターは何度でも見返せる**（振り返れば再確認できる）
2. **外して増えたバイ菌もモニターに反映される**（外しても取り返せる）

### 当てたときの「気持ちよさ」
記憶を頼りに撃ったバイ菌に当たった瞬間が、このゲームのいちばんのご褒美です。
**気持ちのいい効果音とパーティクル**で、黒いバイ菌が白い光ではじけて消える演出にし、「当たった！」という快感をはっきり返すようにしました。

## 実装の工夫

### モニターは「映像」ではなく「枠＋小さな城」
モニターの中の城は、カメラ映像を映しているのではなく、**モニターの枠を作り、その中に小さな城の3Dモデルを置いて**います。
1日で確実に作りきれて、処理も軽く、自分でも作れる方法として、この設計にしました。

### 近づきすぎると「仕掛け」がバレないように
ただし、この方法には弱点があります。モニターを横から見ると、枠と小さな城が立体物だと分かってしまい、「画面に映っている」という見え方が崩れます。
そこで、**モニターに一定距離より近づけないように**制限し、いつでも正面から「モニターの画面」に見えるようにしました。
プレイヤーに違和感を与えないための、小さなUXの工夫です。

## 開発経緯

1. **タイトルから発想**：テーマ「しろ」から、先にタイトル「後ろの白い城を白日にしろ！」を決定
2. **タイトルからゲームを連想**：「白日＝隠れたものを暴く」から、見えないバイ菌をモニターで見つけて消す記憶ゲームに
3. **ジャンルを決める**：作ったことのないジャンルに挑戦したく、FPS系の操作に決定
4. **1日で作れる設計に落とす**：モニターをできるだけ軽く、自分で作りきれる方法として「枠＋小さな城」方式を採用。3Dモデルは自作せず、城はAsset Storeの無料素材を使用
5. **遊び心地を整える**：モニターへの接近制限、外したときの罰ゲーム、当たったときのSEとパーティクルを追加
6. **公開**（2026年7月28日、unityroom）

企画段階の設計メモは [docs/design.md](docs/design.md) に残しています（完成版とは一部仕様が異なります）。

## 振り返りと課題

作り終えてみて、次の点は課題だと感じています。

- **操作方法が分かりにくい**：遊び方を文字だけで説明していたため、読まずに飛ばされてしまうことがありました
- **マウス付きのPCが必須**：一人称視点で照準を合わせる操作のため、ノートパソコンのタッチパッドでは遊びにくくなってしまいました
- **タイトル画面をもっと作り込むべきだった**：ゲームの最初の印象を決める画面なので、もっとこだわる余地がありました

### 次作への反映
公開後、遊んでくれた人からも「文字だけの操作説明は分かりにくい」「あまり読もうと思わず、飛ばしてしまう」というフィードバックをもらいました。

この声を受けて、次作『[セミファイナル](https://unityroom.com/games/semifinal)』では、チュートリアルを**ストーリー形式**にし、**動画のように見られて、実際の動きをシミュレーションできる動的なチュートリアル**に作り直しました。
作って終わりではなく、プレイヤーの反応と自分の反省を、次の作品の設計に活かしています。
